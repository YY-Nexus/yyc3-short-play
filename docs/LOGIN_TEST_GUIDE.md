## 开发模式特性

在开发环境中，系统提供以下便利功能：

### 1. 固定测试验证码
- 账号 `13800138000` 始终使用验证码 `123456`
- 无需数据库连接即可测试登录流程

### 2. 数据库容错
- 如果数据库未配置或连接失败
- 系统会自动为测试账号提供模拟用户数据
- 保证开发调试不受数据库影响

### 3. 详细日志
- 控制台输出 `[v0]` 前缀的调试日志
- 可追踪完整登录流程
- 便于定位问题

## 常见问题排查

### 问题 1：点击登录后提示"登录失败，请稍后重试"

**解决方案：**
1. 检查浏览器控制台是否有 `[v0]` 日志
2. 查看具体错误信息
3. 确认使用的是测试账号 `13800138000` 和验证码 `123456`
4. 访问 `/api/test-db` 检查数据库状态

### 问题 2：验证码发送失败

**解决方案：**
1. 开发环境会自动返回固定验证码，无需真实短信服务
2. 检查手机号是否为 `13800138000`
3. 查看网络请求返回的 response

### 问题 3：登录成功但未跳转

**解决方案：**
1. 检查浏览器控制台是否有路由错误
2. 确认 `/main` 页面是否存在
3. 检查是否有其他 JavaScript 错误

## 生产环境部署

生产环境部署时需要：

1. **配置真实数据库**
   - 设置正确的数据库连接信息
   - 运行初始化和种子脚本

2. **配置短信服务**
   - 集成阿里云短信服务
   - 更新 `lib/services/sms.service.ts`

3. **设置安全密钥**
   - 使用强随机密钥替换 `JWT_SECRET`
   - 不要使用默认值

4. **移除测试日志**
   - 删除所有 `[v0]` 调试日志
   - 或设置日志级别过滤

### 开发模式登录流程

1. **发送验证码阶段**
   ```typescript
   // 如果是测试账号，直接返回固定验证码
   if (phone === "13800138000") {
     return { code: "123456" }
   }
   ```

2. **验证码校验阶段**
   ```typescript
   // 测试账号使用固定验证码
   if (phone === "13800138000" && code === "123456") {
     return true
   }
   ```

3. **用户查询阶段**
   ```typescript
   // 如果数据库失败，返回模拟用户
   if (dbError && phone === "13800138000") {
     return mockTestUser
   }
   ```

### 生产模式登录流程

1. 发送真实短信验证码
2. 验证码存储在数据库中
3. 用户信息从数据库查询
4. 完整的错误处理和日志记录
